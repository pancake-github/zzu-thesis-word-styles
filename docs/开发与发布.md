# 开发与发布

## 组织方式

程序使用 C#、.NET 10 LTS 和 WinForms。核心库负责 OOXML 读取、样式合并、检查、备份及恢复；Windows 集成层负责本机 Word、字体和进程检查；界面组织中文操作流程。核心文件处理不依赖 Office COM，便于用人造文档包测试边界。

`assets/style-spec.json` 从随附 DOTX 提取，包括 26 项目标样式的字体、字号、段落属性、常用库标记和来源说明。模板可能包含 Word 自带的其他隐藏样式；安装程序只能选择批准项，不能把整个来源 styles.xml 覆盖到用户模板。

默认模板安装及 DOCX 副本导入只合并 `word/styles.xml`。目标样式 ID 必须通过安全映射保留，不能假定其他语言的 Word 或长期使用的模板也采用 `Normal` / `Heading1` 等固定 ID。未涉及的自定义样式和其他 ZIP 条目内容必须保留。

## 公开资产准备

`scripts/prepare_assets.py` 接收三个必填参数：`--template`、`--example`、`--output`，均由维护者传入真实文件位置，不包含开发者本机路径。它仅清除公开副本的作者、最后修改者和私人打印时间，逐条比较原包与副本，确保其他部件不变，再提取 JSON 规格及公开清单。

运行脚本的 Python 仅为维护者工具，最终用户不需要它。更新资产之后必须核对样式规格、补充默认值标记及 DOCX 的全部页面渲染；不能仅根据 XML 验证就声明视觉验收完成。

## 构建与测试

以仓库的 SDK 版本文件和 GitHub Actions 配置为准，使用固定 .NET 10 SDK 构建。图形包采用 `win-x64` 自包含目录发布，保留运行时依赖和许可文件；不启用会影响 WinForms / 动态 COM 的裁剪或 NativeAOT。

核心测试使用人造 OOXML 包，不需要 Word。桌面 Word 验收单独运行，并且只能关闭程序自己创建的测试文档和实例，不能杀死用户 Word 进程。纯检查不得启动 Word、保存文档、更新域或安装字体；这些动作属于明确的安装或功能验证入口。

测试时宏自动化安全设置如需调整，应保存并恢复实际原值，不能硬编码恢复到某个预设。对异常、文件占用和 COM 清理使用明确错误处理，不以仅调试时生效的断言保护用户文件。

## 发布清单

只将审核过的程序源文件、测试、配置、原创文档、清理后的 DOTX / DOCX、必要中性截图和构建文件纳入仓库。发布 ZIP 必须由白名单产生，不递归打包开发目录。

禁止纳入个人 Normal.dotm、备份、候选默认模板、真实论文、未经清理的日志、字体二进制、校方附件 ZIP 和完整原始规范 DOC。对 XML、JSON、Markdown、文件名和压缩包内部同时做私人路径与元数据检查。

图形包命名为 `ZZUWordStyles-v0.1.0-beta.1-win-x64.zip`，模板包命名为 `ZZUWordStyles-v0.1.0-beta.1-templates.zip`。两个包的最终字节确定后生成 `SHA256SUMS.txt`，并将同一批文件用于验收及上传。

首版发布为 prerelease。维护者应在发布说明写清已验证的 Word 版本、位数、系统和未完成项目；发布后匿名下载重新核对大小与哈希。修复导致程序或资产变化时重新构建和验证，不以旧测试记录代替新文件验收。
