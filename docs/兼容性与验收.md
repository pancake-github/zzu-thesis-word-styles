# 兼容性与验收

首版为 `v0.1.0-beta.1` 预览版。构建成功只代表代码能够编译，不代表每一种 Windows / Word 组合都已经完成排版验收。下表分别记录目标范围和实际证据，发布前只根据真实结果更新。

| 环境或入口 | 首版范围 | 当前记录 |
|---|---|---|
| Windows 11 x64 + 桌面 Word | 目标环境 | 以本版本发布验收记录为准 |
| Windows 10 x64 + 桌面 Word | 待逐版本验证 | 尚未完成独立环境测试，不笼统承诺全部 Windows 10 版本 |
| 32 位 Office / x64 Windows | 待实际验证 | 进程外 COM 架构可互操作不等于已实测 |
| 64 位 Office / x64 Windows | 目标组合 | 以实际 Office 位数和版本记录为准 |
| 无 Python、未额外安装 .NET 的干净 Windows | 自包含包应支持 | 干净虚拟机验收尚未完成时必须列为限制 |
| Word 内“空白文档”或 Ctrl+N | 核心入口 | 应完成两次独立重启检查 |
| 资源管理器右键“新建 Word 文档” | 单独记录 | 未完成实际入口测试时不得视为通过 |
| 使用其他 DOTX / DOTM 创建文档 | 由对应模板控制 | 修改 Normal 不代表改变这些模板 |
| 已有 DOCX | 副本导入 | 保留直接格式及非目标自定义样式，导入不等于全篇排版合规 |
| WPS、Mac、Word 网页版、32 位 Windows、ARM 原生包 | 不在首版范围内 | 不提供兼容承诺 |

## 必须完成的核心检查

- 26 项目标样式和 12 项常用入口与公开规格一致。
- 文档除样式部分外的包内内容保持一致，包含宏、快捷键、正文、公式及图片对应部分。
- 验证自定义样式 ID、中文/英文内置名称、依赖映射、缺失默认节点和不可识别冲突。
- 相同配置重复安装不改写；安装前后哈希及备份可核对。
- 文件占用、目标并发变化、损坏包和包级签名不会导致静默覆盖。
- DOCX 副本文件名不覆盖既有文件，导入前后的原件 SHA-256 相同。
- 恢复会检测安装后修改，并保护当前版本。

## Word 实际验收

默认正文检查中文宋体、英文 Times New Roman、12 磅、固定 20 磅行距及首行 2 字符。标题检查四级大纲及字体字号，图题和表题检查不同段后间距。使用两次独立 Word 启动及未指定模板的空白文档创建流程，排除只验证独立 DOTX 的误判。

示例文档应检查三级自动目录、四级导航、字体实际显示和全部页面渲染。缺失字体必须按受影响样式报告，不将替代字体呈现算作通过。旧文档副本需检查原件不变、公式/图片仍在，并说明直接格式的保留。

## 发布验证

公开资产必须来自实际验收的同一次构建。上传后使用未登录下载重新核对文件大小和 SHA-256。未完成的环境、入口、代码签名或其他验收项目列在对应 Release 说明中，预发布标签不代表所有兼容性项目已经完成。

验收记录只发布系统/应用版本、测试项目和结果，不发布个人模板、真实论文、完整私人路径或原始操作日志。
